**[CVE-2026-109618 / OOM corruption](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w):** allocation failure can interrupt partially initialized request state, then shutdown consumes it. Multipart parsing or application allocation paths can produce OOM. Unauthenticated HTTP RCE is demonstrated for Apache mod_php before application code; an application login therefore is not sufficient evidence of protection. FPM exits on startup failure, limiting that demonstrated path, but remains potentially susceptible after startup; the advisory does not establish a complete FPM exploit. FrankenPHP is considered likely susceptible and LSAPI conditional. A patched PHP build is the complete mitigation; this audit applies no memory-limit or frontend changes.

**[CVE-2026-109619 / stale global state](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp):** request-owned state must survive cleanup in a persistent worker, then a later request on the same worker must consume it before normal initialization. Early INI diagnostics or session upload progress can supply consumers. FPM frontend-supplied `PHP_VALUE`/`PHP_ADMIN_VALUE` diagnostics are conditional; pool startup values and `.user.ini` do not establish that same early consumer. Suppressing displayed/logged errors does not fix the state access. Exact exploitability depends on build, extensions, SAPI, configuration and reachable operations; it is not established from an image tag or OS name.

**Vendor packages:** [Unraid 7.3.4](https://docs.unraid.net/unraid-os/release-notes/7.3.4/) explicitly updates `php` from `8.4.26-1_LT` to `8.4.27-1_LT`, together with `libvirt-php`. Its release inclusion is verified; installation on Tower is not. [Debian](https://security-tracker.debian.org/tracker/CVE-2026-109618) / [second CVE](https://security-tracker.debian.org/tracker/CVE-2026-109619) list Bookworm `8.2.35-1~deb12u1` and Trixie `8.4.27-1~deb13u1` fixed. [Ubuntu](https://ubuntu.com/security/CVE-2026-109618) / [second CVE](https://ubuntu.com/security/CVE-2026-109619) list Jammy `8.1.2-1ubuntu2.28` and Noble `8.3.6-0ubuntu0.24.04.13` fixed through backports. Compare the installed package's full revision and repository origin against its vendor notice. Older unsupported branches are not implicitly safe; third-party images need their own build evidence.
