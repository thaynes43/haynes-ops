## Relevant changes and compatibility

1. Bundled Node **24.21.0 → 24.22.1** fixes Brotli decoder RCE **CVE-2026-111497**, the release's stated security reason. [Node 24.22.1 release](https://github.com/nodejs/node/releases/tag/v24.22.1) is a security release and also updates OpenSSL to 3.5.9, c-ares and undici. [Node override patch](https://github.com/coder/code-server/blob/279b5702aaff359a8344c9fb8ac0a66d934ff1d6/patches/node-version.diff) explicitly advances VS Code's remote Node target and checksums. The [standalone launcher](https://github.com/coder/code-server/blob/279b5702aaff359a8344c9fb8ac0a66d934ff1d6/ci/build/code-server.sh) executes its own `lib/node`; updating dev-env's general-purpose Node alone does not replace the vulnerable code-server bundle.
2. [HTTP routes](https://github.com/coder/code-server/blob/279b5702aaff359a8344c9fb8ac0a66d934ff1d6/src/node/routes/index.ts) and [session-manager endpoint](https://github.com/coder/code-server/blob/279b5702aaff359a8344c9fb8ac0a66d934ff1d6/src/node/vscodeSocket.ts) set JSON/urlencoded parsers to `inflate:false`, rejecting `br`, `gzip` and `deflate` request bodies. This concerns inbound request-body compression, not compressed responses. Upstream states browsers do not compress request bodies. Any custom caller that does compress them must stop doing so; none is established by the reviewed local launch/config source.
3. Explicit boolean `false` options/config values no longer become `true`. Leading `~` paths now expand to the user's home; `~user` does not. Local HA/ESPHome use absolute `/config` paths and `--auth none`; V1 uses `/home/dev`, `--bind-addr`, `--auth none`, and bare true disable flags. These call sites need no adaptation. No auth default, port, storage schema, base-image target or migration change appears in the diff. Dev-only brace-expansion dependencies also change 1.1.18→1.1.21 and 5.0.9→5.0.12; no additional deployed runtime security claim is made for them.
