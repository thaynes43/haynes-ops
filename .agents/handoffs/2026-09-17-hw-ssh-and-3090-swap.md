## 2. The two 3090s — what is known (do not re-derive; verify with the commands if in doubt)

Both cards are Zotac RTX 3090s and BOTH are physically installed. The board's firmware has
NO slot table (`dmidecode -t slot` empty, no ACPI `_SUN`, every root port says `Slot #0`), so
software cannot print a slot label. It can, however, tell the two cards apart by bus:

| | GOOD card (keep) | FLAKY card (pull) |
|---|---|---|
| Host PCI address | `0000:41:00.0` | `0000:01:00.0` |
| Root port / ACPI | `40:01.1` = `\_SB_.PCI1.GPP0` | `00:01.1` = `\_SB_.PCI0.GPP0` |
| VM 103 | `hostpci1: 0000:41:00,pcie=1` | was hostpci0, removed by Tom |
| NVML id (inside talosw01) | UUID `GPU-d8a856f1-f955-f683-bc24-654561496774`, VBIOS `94.02.42.80.9F`, subsys `0x161319DA` | n/a (never reaches the VM now) |
| Today's state | idle 59 °C, 20 GB VRAM resident (ollama-prime), fans 38 %, link x16 (Gen1 at idle = normal) | link trains at 2.5 GT/s x16 but config space is dead: `pci 0000:00:01.1: broken device, retraining non-functional downstream link … retraining failed` at the 09-10 boot; `vfio-pci 0000:01:00.0: Unable to change power state from D3cold to D0, device inaccessible` in the 08-30 boot; enumerated fine as `[10de:2204]` at the 09-09 boot |

Commands that produced those facts (re-runnable):
```bash
hw-ssh haynesintelligence 'sudo -n lspci -nn | grep -i nvidia'                       # today: only 41:00.x
hw-ssh haynesintelligence 'sudo -n journalctl -k -b 0  --no-pager | grep -E "0000:0?1:00|00:01.1"'
hw-ssh haynesintelligence 'sudo -n journalctl -k -b -1 --no-pager | grep -E "0000:01:00"'
hw-ssh haynesintelligence 'sudo -n journalctl -k -b -2 --no-pager | grep -c "01:00.0.*inaccessible"'
```

**Turning bus → physical slot** (the firmware will not do it; pick one, both are fine):
- **Heat/fans:** the good card is the one that is warm and whose fans spin up under load. Put
  load on it from here right before Tom opens the case:
  `kubectl exec -n ai deploy/ollama-prime -- ollama run llama3.3:70b "Write 1500 words on PCIe link training"`
  (watch `kubectl exec -n ai deploy/ollama-prime -- nvidia-smi --query-gpu=temperature.gpu,fan.speed,power.draw --format=csv`
  climb). The flaky card sits cold/silent. Tom pulls the OTHER Zotac.
- **Pull-one-and-check:** power down, pull either card, boot, then
  `hw-ssh haynesintelligence 'sudo -n lspci -nn | grep -i nvidia'`. If `41:00.0` is still there,
  the flaky card was pulled (the two cards sit on different root complexes, so the survivor's
  address does not move). If instead only `01:00.0` shows and works, the good card was pulled —
  swap them back.
- ASRock's BIOS "System Browser" also shows which slot holds a detected card at boot, if he
  is at the console anyway.

Caveat worth one sentence to Tom: "inaccessible / D3cold → D0 failed / link trains but config
dead" is also the signature of a bad PCIe power cable or seating, not only a dead GPU. If the
NEW card shows the same lines in the same slot, suspect the slot/cables, not the card.
