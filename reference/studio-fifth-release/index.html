    Follow-ups

    Independent review of PR 5110 recorded four follow-ups:

    • A run submitted during a rollout can fail terminally with work.revision_mismatch when the API and claiming worker are on different Studio revisions. Keep submissions closed through postflight.
    • A browser can get HTML from one web revision and an asset 404 from the other while both revisions share the Service, leaving the Editor blank until reload.
    • The read-only command allowlist accepts calls to newly added local helpers without inspecting them.
    • Some release guards lack negative tests, including checks for receipt profiles, rollback prerequisites, encoder agreement and ingress validation.

    Roll back the pins through a reviewed PR

    Expected. The workload rollback remains unexercised on the installed pin.

    Keep submissions closed until active and held work settles. Start the revert from current Ops main. Restore release.yaml, the API, MCP, web, run, voice and image Deployment pins, all four digest-named Job manifests and their Job health-check names in ks.yaml. Apply the reverse of the original pin's patch only, so later unrelated changes remain in place. In this block FIFTH_PIN_OPS_REVISION is the original reviewed fifth-pin squash merge. If a retry added an -rN suffix, first remove that suffix from the Job name in migration/job.yaml and its matching health check in ks.yaml. Then apply this block to restore all four fourth-pin Job names.

    set -o pipefail
studio=kubernetes/main/apps/ai/studio
git diff --no-ext-diff --no-textconv "${FIFTH_PIN_OPS_REVISION:?}^1" "$FIFTH_PIN_OPS_REVISION" -- \
  "$studio"/{release.yaml,ks.yaml} "$studio"/app/{api,mcp,web}.yaml \
  "$studio"/{worker/deployment,migration/job,worker-registration/job}.yaml \
  "$studio"/media-workers/{image,voice}.yaml "$studio"/media-worker-registration/{image,voice}-job.yaml |
  git apply --reverse

    The fourth pin already serves schema 0013. Its migration Job will read back that head if Flux needs to recreate the Job. The render files, policy stages and listener configuration carry forward.
