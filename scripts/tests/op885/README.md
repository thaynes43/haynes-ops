# OP885 talosm03 kernel stall and offline detection

On 2026-11-17, talosm03 reported a Linux file-reference warning in `upsmon` on CPU 7 and a sustained RCU stall in a kubelet thread on CPU 8. Ceph client I/O on the node lost progress while Kubernetes continued to report Ready. Home Assistant and ComfyUI timed out. The file-reference lifetime path is the strongest lead. The record does not identify the original invalid reference, the relationship between the two stacks, or the underlying trigger.

This directory contains an offline Loki rule and a PromQL query for checking RBD progress. Both use observed labels for talosm03. OP884 records an accepted restoration. Installation and acceptance for OP885 remain open. Rollout requires Tom's separate approval. Source base `7e9ad5cca5a3325cd2e7b3cf0170a94f034079ea`.

## Detector and retained replay

The Loki rule emits `TalosKernelRCUStall{cluster="main",node="talosm03"}` from a self-detected, remote or expedited `rcu_preempt` stall header in the last five minutes. It evaluates every minute with immediate firing eligibility. Its output identity is one cluster/node pair even when overlapping CPU reports or retries add to the count. The window uses the stored event timestamp. A file-reference warning by itself is outside the alert expression. The first successful evaluation after the last matching event leaves the window clears firing. With telemetry loss, the resulting node state is unknown. The alert annotation calls for independent checks of RBD progress and service health.

- **Kernel log origin.** Talos v1.13.9 exposes kmsg as the `kernel` service log and embeds the kernel event time in the message. Its normal service logger tags `talos-service` and supplies the outer `talos-time`. GitOps sets `hostname` in talosm03's service-log destination `extraTags`. The only Vector service listener is UDP 6051. The Vector remap maps `hostname` to `node`, `talos-service` to `talos_service`, and uses `talos-time` when parseable. The observed stream has `cluster="main",source="talos",log_type="service",node="talosm03",talos_service="kernel",level="info"`. Kernel severity is in the payload, so the selector ignores `level`. The Vector source and older runbook's dedicated UDP 6050 notes describe a separate path. [Talos kmsg storage](https://github.com/siderolabs/talos/blob/v1.13.9/internal/app/machined/pkg/controllers/runtime/kmsg_log_storage.go) · [Talos service logger](https://github.com/siderolabs/talos/blob/v1.13.9/internal/app/machined/pkg/runtime/logging/circular.go) · [Vector remap](../../../kubernetes/main/apps/observability/vector/app/resources/vector.yaml) · [Omni source](../../../kubernetes/main/bootstrap/omni/cluster-template.yaml)
- **Evaluation and coverage.** At `18:52Z`, Loki and Vector were on talosm05, Prometheus and Gatus on talosm02, and kube-state-metrics on talosw03. The existing Loki kernel rule group is scheduled at 60 seconds (`/prometheus/api/v1/rules`). Prometheus is configured for 30-second rule evaluation and 60-second node-exporter, kube-state-metrics and Gatus scrapes, verified by the runtime CR and retained timestamps. The Ceph mgr samples in the incident window were 10 seconds apart. Both candidate queries are evaluated outside talosm03 and require no Ready transition. Seven of nine nodes had at least one retained kernel line in the 24 hours ending at midnight after the incident. The matching signature returned talosm03 only across a seven-day query. Sparse or absent lines can reflect quiet kernels, forwarding loss, or an unavailable collector. [Loki ruler wiring](../../../kubernetes/main/apps/observability/loki/app/helmrelease.yaml) · [Prometheus and node-exporter wiring](../../../kubernetes/main/apps/observability/kube-prometheus-stack/app/helmrelease.yaml)
- **RBD signal.** Node-exporter's Linux diskstats collector supplies `node_disk_io_now` and the two completion counters. The ServiceMonitor copies the exporter pod's node into `kubernetes_node`. The `instance` label is an address and port, and each `device` is local to that node. The query requires three samples of each field in three minutes, positive in-flight requests at every sampled point, both counters unchanged, and a latest scrape at most 75 seconds old. The three latest disk samples must share a timestamp with the matching exporter's latest `up=1` sample. The query matches exporters before reducing to node/device, so complementary fields from different exporters cannot be joined. A reset or observed completion breaks the match. Ready comes independently from `kube_node_status_condition{node="talosm03",condition="Ready",status="true"}`. Its `node` label identifies the monitored node while `kubernetes_node` identifies the exporter pod's node. [Node-exporter diskstats](https://github.com/prometheus/node_exporter/blob/master/collector/diskstats_linux.go)

The operator retains the mode-0600 JSONL ledger on the session's local home volume for seven days after the run, then removes the private run directory. The ledger holds timestamps, counts, digests, an RCU header flag and result states. The observer writes only this local file and has no notifier, export or remediation consumer. Record the exact commit, stop reason and summarized evidence in OP885. If cancelling early, press Ctrl+C in the foreground terminal or send `SIGTERM` to the observer PID from the start record after verifying it is the same process. Rollback is stopping the observer and checking that the process exited and the ledger stopped growing. An incomplete or missing terminal record makes the run inconclusive.

For each unique stream, Loki timestamp and payload, the ledger records first visibility in a complete poll, deduplicated across the overlap. The upper bracket is the first complete response's receive time. The lower bracket is the previous complete poll's request start, only when its query covered the timestamp, that snapshot lacked the entry, and the schedule between the two was intact. The upper bracket still records observed presence when the lower bound is missing. Warm-up, gaps and timestamps ahead of the observer clock leave the corresponding bracket inconclusive. Saturation, incomplete replies, timeouts and missed slots invalidate coverage. Even complete snapshots only sample records the endpoint returned. An upstream drop or arrival outside the lookback can go unseen.

Use at least 20 fresh bracketed kernel records with event timestamps during the run. Proposed gates are a nearest-rank p95 `upper_delay_ns` of at most 35s, maximum at most 120s, and a full schedule with zero gaps. These are bounds on observed queryability relative to Loki event time. They include polling and response time and depend on the verified clock offset. A record that becomes queryable more than four minutes after its timestamp may miss a one-minute evaluation phase. The five-minute rule window determines event-time eligibility.

Each evaluation records `recent_match` or `no_recent_match`. If a successful match later becomes absent, the ledger records that transition and keeps node health `unknown`. A quiet stream, a window expiry and the run's own expiry all leave health unknown. Separate I/O and service evidence would be needed to determine recovery. If a genuine RCU header is witnessed, inspect the first eligible tick whose request starts after the visibility upper bound and whose scheduled timestamp falls inside the five-minute event window. A tick inside the bracket has uncertain visibility. If there is no RCU header with an eligible tick, production positive detection remains unverified. The observer tests use mocked responses and loopback only. Production queryability, coverage, installation and acceptance remain open under OP885.
